# Prisoner 15

Hand-built Android APK, no Gradle and no libraries. Package `pl.prisoner15`. WebView UI in `app/assets/index.html`, training engine in `app/assets/engine.js`, sensor and reminder in `app/src/pl/prisoner15/`. Interface text is English.

Status and roadmap: `PLAN.md`. Context material: `docs/plan.txt` is the owner's original plan. `docs/naked-warrior.md` is the training basis (Pavel Tsatsouline, *The Naked Warrior*): read it before changing the training logic, and keep only our own summary there, never the book's text or photos.

Rules:

- Strength work is only push-ups and squats; the Run screen is a separate Galloway run-walk timer. A session never exceeds 15 minutes (`LIMIT`, `BUDGET` in `engine.js`).
- Every session has two halves, the same for push-ups and squats (`sessionPlan` in `engine.js` is the only place these rules live): the warm-up half is always the first 2 rounds, standard push-ups and squats (0.6 of capacity, flat); the heavy half is the remaining rounds, uneven push-ups and Bulgarian split squats, both sides each round. Rounds 2 = standard only; 4 = 2 + 2 one-sided; 6 = 2 + 4. Exhausted, a missed day and Sunday give 2 rounds. Mon/Wed/Fri moderate, Tue/Thu/Sat light, Sunday recovery. When the time budget cuts rounds it cuts heavy rounds, never the two standard ones.
- Owner's training rules, never break them: the number of rounds is always even (2, 4 or 6); one-sided exercises (uneven push-ups, Bulgarian split squats) are always done in pairs with exactly equal repetitions on both sides (`P.target`, `P.hasFirst` in `engine.js`); no static back exercises (no planks or similar); the owner wants the absolute survival minimum.
- Running (Run tab) is flexible and never changes the strength plan: every second day is suggested, not required; a run of 20 minutes or more counts as done, longer is welcome (the timer goes past the target until stopped), shorter is logged. 5 km is a future goal, not the current one. Progression: run/walk steps (`LADDER`), two comfortable done runs step up.
- Paths (the Path section of the Record screen, `PATH` in `engine.js`): six steps from the uneven push-up to the one-arm push-up and from the Bulgarian split squat to the pistol. Moving up is the owner's choice (two taps), only after the capacity reaches 10 (`GRAD`); the capacity then restarts at half. Only floor, books, a chair or a low table. The steps are ours from general sources, not from the book. The path levels apply to the heavy-half variation.
- Removed in v1.1.0, only back if the owner asks: 1-2-3 ladders and walking and running detection (step sensor). Old runs may still hold `steps` and `km` in the data; they are not shown.
- The saved state is upgraded in one place, `migrate(state)` in `engine.js` (`state.v` is 2); it is called when the app loads and when a backup is loaded (backups with v 1 or 2 are accepted). The owner's history must survive every update.
- Push-ups are counted by touching the marked pad with the nose (counted at first contact, `pointerdown`); the proximity sensor is optional. Cues on the Run screen must be loud enough for noise (alarm volume).
- No network permission, no accounts, no added libraries.
- Never commit `*.keystore`, `*.jks`, `signing.env` or APK files.
- **Signing key:** it lives only in the private GitHub repository `jacekkotowski/apk-signing-keys`, folder `apk-prisoner-15` (files `prisoner15.keystore` and `signing.env`, same arrangement as `apk-heart-sounds`). Before building, get it from there: attach that repository to the session, copy both files into the project root (they are git-ignored), then run `./build.sh`. Never generate a new key: an APK signed with a different key cannot update the installed app and the user's history would be lost. Check the build with `apksigner verify --print-certs`: the certificate SHA-256 must be `8be0199b1c6af26849f1ff522e616a053ca1130c10253df85f139327a8b781cf`. If the key is missing from that folder, stop and ask the user.
- Source lives in `jacekkotowski/apk-prisoner-15`, branch `main`.
- **Releases (standing instruction from the owner):** every delivered build is also published as a GitHub Release in `jacekkotowski/apk-prisoner-15`: tag `vX.Y.Z` (the version name), the compiled, signed APK attached as `Prisoner15-X.Y.Z.apk`, and notes saying what changed and what was not tested on a phone. Never leave a delivered build only in the chat. It is automated: `.github/workflows/release.yml` tests, builds, signs (secrets `KEYSTORE_B64` and `KS_PASS`) and publishes the release when a tag `vX.Y.Z` is pushed, or when the owner runs it from the Actions tab with the version. After delivering a build: write the notes in `docs/releases/vX.Y.Z.md`, commit and push `main`, then `git tag vX.Y.Z && git push origin vX.Y.Z`, and tell the owner whether the release run succeeded. The tag must equal `versionName` in the manifest. If the tag cannot be pushed or the run fails, say so plainly and hand the owner the APK and notes; do not work around the session's restrictions. The repository is public, so releases are public; an APK never contains the key.
- Run `node tests/engine.test.js` and `node tests/ui.js` before handing over a build (the Release workflow runs both; the Java side compiles only in that workflow's build, since this machine has no Android SDK). State plainly what was not tested on a phone.
- Raise `versionCode` and the version name with each delivered build.
